# UniConnecT — AI Learning Paths + Quiz Review Gate

## Context

Two things prompted this plan:

1. **A live bug**: the `/learn` page's leaderboard panel throws a 500 (confirmed in the browser Network tab — `GET /quiz/today/leaderboard`). Root cause found: `apps/api/src/modules/quiz/service.ts`'s `getTodayLeaderboard` joins `users` and selects `u.full_name`/`u.avatar_url`, but those columns live on `profiles`, not `users` (Postgres throws `column u.full_name does not exist`, uncaught, surfaces as a 500).

2. **A feature gap**: today, AI-generated content on the Learn page flows straight to students with no admin control or review —
   - **Learning paths** (`skill_paths`/`skill_path_units`) are *only* ever created via a hardcoded seed migration. There is no admin authoring UI, and no AI generation of paths at all.
   - **Daily quiz questions** (`ai_quiz_pool`) are generated by Gemini on an unconditional cron for every university/department and flow straight into `daily_quiz_slots` with zero settings or review gate.
   - **Flashcards** (group-level, academic groups only) already have exactly what the user wants: an admin-configurable `require_approval` toggle and a faculty approve/discard review queue (`groups/service.ts` — `ai_settings`, `listPendingAiContent`, `approvePendingAiContent`, `discardPendingAiContent`). This is the reference pattern for the quiz-review gate below, and needs **no changes**.

The intended outcome: bring learning paths and quizzes in line with flashcards — admin sets preferences, AI generates content against those preferences, and nothing reaches students until an admin (for paths, always; for quizzes, only if the admin opts in) approves it.

## Requirements (confirmed with user)

- **Learning paths**: admin preferences cover (a) a topics/subjects list, (b) difficulty + language + estimated-length defaults, (c) generation cadence (cron hour) + count per run, (d) free-text custom instructions. AI-generated paths are **always** review-gated — no opt-out, since there's no existing auto-publish behavior for paths to preserve.
- **Quizzes**: review gate is an **opt-in** `require_approval` toggle, default **off** (preserves today's auto-flow for admins who don't touch the setting) — exact same shape as the existing group-level flashcard toggle.
- **Flashcards**: unchanged, already correct.
- Full build now (schema + backend + frontend + tests), executed via `superpowers:subagent-driven-development` the same way as the prior 31-task academic-lms plan — fresh implementer + reviewer subagent per task, task briefs, progress ledger, final whole-branch review before merge.

## Architecture

- New admin-owned settings live as columns on `university_settings` — mirrors the content-sync precedent (`059_add_content_sync_settings.ts`, `075_add_content_sync_entries_per_source.ts` both just added columns there). 9 new columns is comparable in size to content-sync's, so a dedicated table isn't justified.
- `skill_paths` gets a `source` column (`'manual' | 'ai'`, default `'manual'`) so the review queue can distinguish AI drafts from existing hand-seeded rows without touching `is_published`'s existing default-`true` manual-authoring semantics.
- `ai_quiz_pool` gets a nullable `is_approved` boolean, used only when a university's `ai_quiz_require_approval` is `true`. `null` = pending, `true`/`false` = actioned. When the toggle is off (default), rows behave exactly as today — untouched, immediately consumable.
- New `apps/api/src/modules/learning-admin/` module (separate from the read-mostly student-facing `modules/learning/`) exposes `/api/v1/admin/learning/...`, mounted next to `adminRouter`/`contentSyncRouter`.
- Generation logic lives in `ai-content.worker.ts`, extending the existing `runQuizGeneration`/`runGroupPosting` pattern with a new `runLearningPathGeneration()`.
- **Cadence is per-tenant** (`ai_learning_gen_hour` column, not a global env var) — this follows directly from the user's explicit choice that cadence is an admin preference, not a platform config. The generation job runs hourly and each university's row is only processed when `genHour` matches the current UTC hour.
- Reuses `ai.service.ts`'s existing (currently unused) `generateSkillPath()` — extends its signature, matching `generateQuizQuestions`/`generateFlashcards`'s existing pattern. Reuses `rateLimitedAICall` from `ai-content.worker.ts` rather than building a second limiter.
- Frontend: new `apps/web/src/features/learning-admin/` (hooks + `LearningAdminPanel.tsx`) and a new "Learning" tab in `AdminPage.tsx`, directly templated on `ContentSyncPanel.tsx`'s settings-form + generate-now + pending-review-queue + run-history structure.

## Global Constraints (every task)

- Migration numbering starts at `097` (tip is `096_create_session_notes.ts`).
- `universityId` always from `req.university.id`, never request body.
- No soft-delete here — these are admin-curated draft/live rows; follow `skill_paths`' existing `is_published` boolean convention.
- Response helpers `sendSuccess`/`sendPaginated` only. Errors via `notFound()`/`forbidden()`/`badRequest()`/`conflict()`.
- Body validation via `validate(schema)`, query validation via `validateRequest({ query })`.
- AI generation always runs through the existing `aiContentQueue` (Bull) — never invoked inline from an HTTP handler. The "generate now" button enqueues a one-off job, it does not call the generator directly.
- All new admin routes gated `requireAuth, resolveUniversity, requireRole('admin')` at router level (matches `contentSyncRouter.use(...)`).
- Route files contain only `router.METHOD(...)`; logic in `service.ts`; controllers wrapped in `asyncHandler`.
- `npx pnpm typecheck && npx pnpm lint` clean before any task is done; run `npx pnpm --filter api test` / `npx pnpm --filter web test` for touched packages.
- Frontend: design tokens only (`var(--surface-card)`, `var(--border-default)`, `var(--r-lg)`, etc. — copy exact tokens from `ContentSyncPanel.tsx`), 0.5px borders, pill buttons, font-weight 400/500 only, sentence case.
